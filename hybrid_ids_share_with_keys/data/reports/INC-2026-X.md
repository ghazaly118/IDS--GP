# Incident Report: INC-2026-X - DDoS Attack on prod-web-01

## 1. Incident Overview
*   **Incident ID:** INC-2026-X
*   **Attack Type:** Denial of Service (DDoS) - UDP Flood
*   **Severity:** High
*   **Victim Hostname:** prod-web-01
*   **Target IP:** 10.0.0.5
*   **Attacker IP:** 185.220.101.5
*   **Target Port:** 80
*   **Protocol:** UDP
*   **Flow Packets:** 450,230
*   **Flow Bytes:** 582,310,400
*   **Flow Duration:** 15.2 seconds
*   **Detected By:** ML IDS Alert (Confidence: 0.985)

## 2. Forensic Analysis

### 2.1. Initial Observations
*   An ML-driven Intrusion Detection System (IDS) alerted on a UDP Flood (DDoS) attack targeting `prod-web-01`.
*   The attack originated from `185.220.101.5`, which resolved as a public Tor exit node, indicating an attempt at anonymity.
*   High volume traffic (450,230 packets, 582,310,400 bytes) was observed over a short duration (15.2 seconds).
*   Nginx connection logs on `prod-web-01` confirmed massive ingress traffic rates exceeding standard bandwidth thresholds on HTTP listener port 80.
*   The attack utilized UDP protocol on port 80, which is highly unusual for HTTP services that primarily use TCP. This suggests a deliberate attempt to bypass stateful firewalls, exploit potential UDP-based services running on port 80, or simply to generate unstateful, high-volume traffic for resource exhaustion.

### 2.2. System Context
*   **Host Role:** Public Web Gateway
*   **Criticality:** High
*   **Impact:** The denial of service attack significantly impacted the availability of the public web gateway, disrupting legitimate user access and potentially other dependent services.

### 2.3. Threat Actor Analysis
*   The use of a Tor exit node suggests the attacker aims to obscure their origin. The motive appears to be service disruption or resource exhaustion rather than data exfiltration or system compromise, at least in the initial phase.

## 5. Response Plan (Containment Actions)

Based on the immediate threat and the nature of the attack, the following containment action is recommended:

*   **Action Type:** Block IP
*   **Target:** `185.220.101.5`
*   **Description:** Implement an immediate block on all incoming traffic from the attacker IP address (`185.220.101.5`) at the perimeter firewall or a dedicated DDoS mitigation service to prevent further resource exhaustion on `prod-web-01`.
*   **Status:** Pending

### 5.1. Further Recommendations

*   **Network Monitoring:** Enhance monitoring for unusual traffic patterns or spikes, particularly on critical public-facing infrastructure.
*   **DDoS Mitigation Review:** Review and strengthen existing DDoS mitigation strategies, including rate-limiting, traffic scrubbing, and blackholing capabilities for all public-facing assets.
*   **Protocol Hardening:** Investigate why UDP traffic on port 80 is being accepted or processed by the web gateway and implement stricter filtering if no legitimate UDP service is expected on that port.
*   **Security Posture Review:** Conduct a broader review of the security posture for all public-facing web gateways.
*   **Threat Intelligence Integration:** Consider integrating threat intelligence feeds to proactively block traffic from known malicious Tor exit nodes or other high-risk IPs, if business requirements allow.

## 6. Conclusion
The `prod-web-01` host experienced a significant Denial of Service attack via a UDP flood, originating from a Tor exit node. The attack successfully impacted the availability of the critical Public Web Gateway. Immediate containment by blocking the source IP is crucial, followed by a comprehensive review of DDoS mitigation strategies and network hardening to prevent future occurrences.
